# Findings: mode-specific worksheet over current editor core

**Works:** `openWorksheet({ mode, store, contentSchema, answersSchema, feedbackSchema, initialSnapshot })` accepts a caller-owned writable `NodeStore` (Flat or Yjs). It exposes exactly one writable document; other documents are independently created `ReadonlyNodeStore` snapshots. Demo snapshots all three documents on mode change, applies downstream resets, constructs a **new** `FlatNodeStore` and worksheet, and remounts editor with a new key. No store survives a mode switch. Existing stored unit IDs link answers and feedback; edits to earlier documents are retained. Browser test covers authoring → answering → grading → viewing → answering → authoring.

## Changes required inside copied core

- `editor/worksheet.ts`: previous code opened content, answers, and feedback independently on same store root. `root.getOrCreate` has one root, so second schema bound wrong root. Open one object root containing all three schemas; expose selected child and reconstruct the other two from read-only snapshots. This also avoids changing storage backends.
- `editor/schema/discriminated-union.ts`: block definitions have additional `id` and fields; original generic constraint (`TaggedFields`) reduces their snapshot type to `never`. Narrow constraint to empty fields and assert default snapshot membership (first definition is in union).
- `editor/rich-text/definition.ts`: gap marks previously discarded IDs on JSON import and DOM serialization. Stable mark IDs are needed to associate answer keys across snapshots; copied gap mark definition from first experiment.
- `editor/schema/exercise.tsx`: feedback mode previously threw when an exercise had no saved answer, including when user skips answering. Render/grade against read-only default answer instead; do not persist an answer during feedback.

Remaining core limitations: `Worksheet` context defaults to tagged response records, so application-specific feedback shape needs a record entry (`__overall`) for overall feedback. A typed context parameter or schema-independent exercise resolver would avoid that convention. Schema `ReadonlyNodeStore` still constructs ProseMirror editors for locked rich text, even for static rendering; optimizing that would require a separate lightweight reader. Flat store has no explicit disposal API: remount unmounts views and old store becomes collectible, but callers using Yjs must also destroy their old `Y.Doc`/awareness and disconnect providers after snapshotting. No cross-document atomic save, persistent serialization, authorization boundary, or migration of answers after content ID changes; debug JSON exposes solutions.

Demo uses one local editor instead of previous Yjs collaboration pair: collaborator sessions cannot survive navigation-style mode switches. `openWorksheet` stays backend-neutral; to try Yjs, pass a new `YjsNodeStore` with a new `Y.Doc` and awareness for each mode, then tear down that session on switch. No additional storage facade required.
